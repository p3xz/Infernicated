2. What data is processed

infernicated has no accounts, no backend server, and no database. The table below reflects exactly what the code does, checked directly against the source.

Data What actually happens
Password typed into the analyzer Read only in browser memory to calculate a strength score. Never sent anywhere, never written to disk, never logged. Cleared when the page is closed or refreshed.
Password hash (breach check) Hashed locally with SHA-1. Only the first 5 characters of that hash are sent to the Have I Been Pwned API. The full password and full hash never leave the browser.
Generated passwords Created locally using the browser's secure random source. Never transmitted or stored.
IP address / standard request metadata Not read, logged, or stored by infernicated's own code. As with any website, the network infrastructure serving the page (and the Have I Been Pwned API, and the Google Fonts CDN, when contacted) will ordinarily see a visitor's IP address as a normal part of handling an HTTP request — this is outside infernicated's code and depends on where it is hosted. See "Third-party services" below.
Cookies None are set by infernicated.
Analytics / tracking None is implemented.
Accounts, billing, support submissions Not applicable — these features do not exist in infernicated.

3. Why data is processed

Only two purposes exist in the current implementation:

  • Performing local password strength analysis, so the tool can show a score and report.
  • Checking a hash prefix against Have I Been Pwned, so the tool can report known breach exposure.

There is no purpose related to advertising, profiling, analytics, or resale of data, because none of those mechanisms exist in the code.

4. Legal basis

infernicated does not operate accounts, does not require sign-in, and does not knowingly retain personal data after a session ends. Because of that, most GDPR-style legal-basis categories (contract, consent, legal obligation) do not clearly apply, since there is no ongoing processing relationship with a user.

Where the tool does briefly transmit data (the 5-character hash prefix sent to Have I Been Pwned), the closest applicable basis would be legitimate interest — performing the specific function the user actively requested (a breach check they triggered by clicking Analyze).

Flagged for review: this is a reasonable interpretation, not a legal determination. If infernicated is deployed in a context where GDPR, DPDP, or another privacy law formally applies, the legal basis should be confirmed by someone qualified to assess it against the actual deployment and jurisdiction, rather than relying on this description alone.

5. Cookies & browser storage

infernicated does not use cookies, localStorage, sessionStorage, or IndexedDB. This was verified directly against the source code, not assumed. No consent banner is shown, because there is nothing non-essential to consent to — adding one would misrepresent what the site actually does.

6. Third-party services

infernicated's own code makes requests to exactly two external services. No others are contacted by the application.

Service Purpose What it may process
Have I Been Pwned — Pwned Passwords API (api.pwnedpasswords.com) Breach exposure check, only when the user clicks Analyze A 5-character hash prefix, and standard request metadata (such as IP address) as seen by any web request. Never the password or full hash.
Google Fonts (fonts.googleapis.com, fonts.gstatic.com) Loading the Inter and IBM Plex Mono typefaces Standard request metadata (such as IP address and browser information) as seen by any font file request. No password-related data is sent to this service.

Missing information: the hosting provider or CDN used to serve infernicated itself is not yet determined (this depends on where the project is deployed — GitHub Pages, Netlify, Vercel, etc.). Whoever hosts the static files will also see standard visitor request data as an ordinary function of serving a website. This section should be updated with the actual hosting provider once deployment is finalized.

7. International data transfers

Have I Been Pwned and Google Fonts both operate global infrastructure, which may mean requests are processed outside a visitor's own country. infernicated's code does not control or configure this — it is a property of using those third-party services.

Flagged for review: a precise international-transfer assessment depends on where infernicated itself is hosted and where its visitors are located, which cannot be determined from the static codebase alone. This should be confirmed once hosting is finalized.

8. Your rights

Because infernicated does not create accounts and does not knowingly retain personal data after your session, most data-subject rights have limited practical application here — there is typically nothing stored to access, correct, delete, or export. For completeness:

  • Access — infernicated does not retain a record of your password or analysis results after your session ends, so there is nothing on file to request.
  • Correction — not applicable, for the same reason.
  • Deletion — not applicable in the ordinary case, since nothing is stored. If you believe any data has been retained in error, contact us using the method below.
  • Objection / restriction — you can stop using the tool at any time, which stops all processing immediately, since processing only happens while you are actively using the page.
  • Portability — not applicable, as no ongoing personal data set exists to export.

No automated request-handling system exists for these rights. Any request would currently be handled manually by the project's author.
